为什么高效率的通用robot learning不可能实现

两年前看金博的一篇振聋发聩的文章轨迹规划，行为决策，与隐变量，深刻体会到了 planning 的技术潜力。如今再读仍然非常超前，似乎极少有人意识到这篇技术文章实际意味着什么。斗胆写一篇解读和延伸，希望更广泛的读者能够读懂文章在技术讨论背后的东西。

回观历史，在 MDP 的荫蔽下，发展出两个技术路径：1. 用 controller 等价 planner；2. 用 planner 等价 controller。

第一个路径是将 planning 问题烘焙到 controller固化下来，以期获得最好的性能。最初打导弹放卫星那会儿，大伙只能离线优化一个 action sequence 作为 policy，附带一个名义轨迹。因为名义轨迹附近的性质是不清楚的，谁也不知道实机跑起来怎么快速修正偏差。此时 MDP 的概念就显得十分重要，因为这意味着总可以离线算一个定义在状态空间子集（例如名义轨迹附近）上的反馈律，这样跑偏的情况下也可以快速诱导出新的最优轨迹。逐渐地，先规划再控制成了一件自然的事情；一些应用场景会离线计算出整个状态空间上的最优反馈律，以满足极端实时性需求，例如制导里的比例反馈律等等。当然，这一路径的困难是，高维状态空间上的解表示有维数灾难，而这一路径给出的答卷是 ADP/RL，用 feedback map 作为 policy，再用低维参数空间 表征 。

与“为性能做极致优化”不同的是，第二个路径是用在线 planning 隐式定义 controller，从而大大降低设计和维护的认知负担。最初在化工领域，由于存在时滞、MIMO耦合、复杂约束问题，一个性质优良的 controller 不太容易设计整定和维护，就发展了 MPC。MPC 是滚动时域情形下的 OC，只要问题是 MDP 且在 上存在可行解，就总存在一个 上反馈律与之等价；因此，如果系统设计成熟可以固化，将 planner 烘焙成 controller 是一个自然的做法，反正MDP情形有理论保证；而对于开发者来说，只要优化器基础设施给力，会倾向于将 planning 作为建模方案和认知框架，因为在大部分情况下，定义objective、ODE、约束远比定义 controller 直接且方便得多。

其实滚动时域能 work 的场景并不广泛，只是它太出名了。实际上 online planning 的玩法非常灵活，MPC 只是十分特殊的情形。

第一条路径的代价是考虑 上的表征，低误差要求下，参数量随维度上升而指数上升，即维数灾难，但这一问题发生在表征上，并不必然发生在在线查表上；而第二个路径中，决策空间是动作序列 ，在线 planning 是在无穷维决策空间上求不动点，但时间离散化后，不动点迭代对离散动作序列的时间复杂度是多项式级的——时间离散化 步、 ，如果设固定迭代次数上限，那么稠密问题有 。

planning 的目的一般不是求全局最优，因此不必然是 np-hard 的。在一些好的设计下，固定迭代budget 就足以收敛到好的不动点了。

也就是说，controller 那一边实时性强，但对维数的暴增完全不可接受；而 planning 这边，有一个很慢的起点、实时性需要更好的求解器基础设施保证，但对维数增加并不敏感（至少是多项式的）。这两者各有好处，从实际出发，选择一条符合需求的就好了。

不过上述讨论有个前提：一个连续问题还能被建模成低维 MDP！

二、planner 能做到 controller 做不到的事情

当代决策/控制问题变得非常复杂，在建模时会涉及不可避免的跨时间关系，这样就会涉及到 path-dependent objective。

一些常见的简单 path-dependent 特征是可以用有限维状态增广、使问题MDP化的：

  • 历史总累计值，或固定fir filter下的累计值。只需积分累计量
  • 历史总最大/最小值。只需最大/最小滤波保持
  • 历史简单统计量，如均值、方差。可以构造成上述累计量
  • 距某个事件经过多久。用事件触发计时器即可
  • 固定时空集合下的占据特征（例如是否在某时空集合中出现过）。按历史累计即可
  • 固定事件集合的触发顺序。

容易发现，上述可有限维MDP化的特征都只面向固定历史时间区间。一旦需要任意查询/动态定义某个时空支撑集，就不再存在“可有限维MDP化的增广状态空间”了，决策者必须维护完美历史记忆。例如：

  • 一个带时滞的 feature
  • 动态定义长度的滑动窗口积分。新信息进入窗口时，还需要知道离开窗口的旧信息，这意味着需要维护一段时间的稠密信息。
  • 动态定义时间区间上的最大/最小值，同上；类似地，精确历史数据分布和在线分位数等等同理。
  • 动态定义时空集合上的占据特征。
  • 完整频谱，相当于需要维护无穷多个filter的积分。
  • 朴素的历史轨迹。例如需要严格沿原路径返回。

同样的原因，上述特征也可能沿时间向前伸展，依赖未来轨迹。例如打乒乓球，观测对方击球动作和球空中轨迹，对不可能的旋转方向剪枝后，仍然需要预设球在击中台面之后多种可能的轨迹，并且保证在最可能的情形下获利、且任何情况下不会吃亏。这样的设计非常直观，若强行建模成MDP，会极大增加认知负担。当然也有沿时间稠密的问题。

如果建模框架不能与上述特征相容，很多简单问题都解决不了。例如做菜，食材的加热处理需要依赖厚度、加入时间、翻炒程度以及经验上的时间（熟度不能被任何感官直接测量）；战场上需要用听觉观察对方是否在换弹，结合预估的换弹时间，与露头、观察、确定位置、瞄准的所需时间，判断是否主动出击；打网球时需要对来球轨迹做预估，需要动态调整和综合评估未来击球点处是否是上升区/抢节奏、自身重心的稳定性、调整时间/能多大程度给予对方压力等等；交通法规定变道后N秒被追尾才无责，那么评估变道风险，就需要 objective 依赖完美记忆。

如果建模时有必要利用上述特征，则问题本身不可被有限维增广状态 MDP 化。这意味着“可以编码解的有限维 controller”的存在性没有理论保证。当然了，时间离散化后当然可以用 controller 编码，但维数灾难不是闹着玩的，表征复杂度 也同时意味着，同样的拟合精度下，所需数据量也要指数上升。特别注意：

  • 这类情况不满足所谓低维流形假设。想得到 feedback policy，就要真刀真枪地处理 sequential decision making 最可怕的一面。
  • 这里说的增广状态空间是指沿时间轴增广。单帧图片那种增广解决不了问题。
  • 在 RL 中的reward里维护完美记忆、设计非马尔可夫reward等等并不改变结论，因为可编码解的 feedback policy 必需定义在超高维增广状态空间里。如果不用增广状态空间，那policy 不会收敛到“解”上，一切相关的设计将没有任何用处，因为此时 NN 没有相应的表达能力，所期望的机制读不到所需的信息。

与此同时，依赖完美记忆与否对 planning 来说确实会影响求解效率，但最坏情况仍然是 。

因此，只要 robot learning 还是指 “学习 feedback policy” 这类范式，那么通用、高效率的 robot learning 是不可能实现的。在算力越来越便宜的当代，实际上应该重新重视 planning。“controller 与 planner互相等价” 的做法，作为系统级技术路径已经远远过时了，只会作为模块嵌入在整个大系统内；“healthy learning component”确实也没啥问题，但完全不足以支撑“通用”。

因此，考虑系统级技术路径，通用机器人要么是learning+中心化大算力平台+漫长、以十年计的数据收集；要么走捷径，直接以 planning 作为复杂决策系统的核心。我没说learning不可能达到目的，只是说robot learning+去中心化是毫无希望的。这是从技术逻辑出发的判断。
