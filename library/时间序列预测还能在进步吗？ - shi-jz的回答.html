时间序列预测还能在进步吗？

按照现在的范式，时间序列预测不仅不太能进步，而且已经走偏了。

我们最近的一个position paper里面详细分析了导致目前时间序列预测方法状况频出的最根本原因——这个领域目前的范式存在内在冲突：

现在很多时序预测的做法还在把 Electricity / Traffic / Weather / ETT 那几套 benchmark 当成“ImageNet”，然后指望改进Informer, FedFormer, PatchTST, iTransformer, ModernTCN, DLinear, etc.等出一个“更强的通用 backbone”，来做所谓时间序列预测的问题；之前有人发现了这种做法的一些问题，比如超参敏感、不一定打得过传统方法等，针对性给出了比如注意eval误差、要增大dataset等解决方法。

但是，我们给出了一个尖锐的position：这不是暂时没做到，而是方向本身就内含矛盾。

我们的position：试图去找到一个时间序列预测的通用架构（类似从Informer开始的架构探索）的道路走不通。原因不是架构/hyperparameter/误差等等问题，而是General Domain TSF这个领域本身存在不可调和的冲突。我们的Position Paper里面重点分析这种不可调和性。

我们的核心观点：TSF 里存在一个“不可调和的 conflict”

我们提出的 conflict 很简单：

  • 想要跨域泛化（general-domain） → 就得把各个领域“独有的上下文、结构先验、生成机制”扔掉，保持统一接口与统一输入（只看所有time series共享的先验）。
  • 想要单域 SOTA（single-domain） → 就必须把这些“领域信息”吃进去：物理约束、空间场、制度与微观结构、因果驱动、外生模态……否则就永远差一截。

这两件事在一个固定架构里会互相掐死： “泛化”要求丢掉关键信息，“SOTA”要求必须利用关键信息。

接下来我们反过来：我们时序预测社区里种种的怪异现象都能被这个 conflict 统一解释了；然后再来分析这个conflict的成因。

（一）为什么会不断看到 TSF 社区的“怪现象”

TSF社区看到的这么多怪现象，很多可以用这个Conflict解释。如下：

1）“深度模型不一定赢传统方法”

社区里早就反复出现：在所谓 general-domain 任务上，ARIMA / ETS / Theta 这类统计方法经常能顶住甚至赢过很多“新 SOTA 神经网络”。为什么？ 当强行统一问题定义时，我们得到的“通用数据性质”太少，少到传统方法就够用了。

哪怕通用方法效果和传统方法接近，但只要有一定提升，不就可以继续研究吗？然而：

2）榜单“近乎饱和”+“调参决定一切”＝方向开始自证其伪

另一个更难绷的点：general-domain TSF 的指标越来越难提升，甚至出现“准确率极限/饱和”的讨论；同时，模型排名对超参、预处理极其敏感——以至于一堆模型都能通过“合适设置”刷成平均意义上的 SOTA。很多之前的工作提了很多点，比如“数据集小”“没有好好调整超参数”“没有做好误差分析”。但是我们认为关键在于： 在一个信息量有限、天花板很低的赛道里卷结构，一下子就卷到头了。

3）最讽刺的信号：真正做单域的人，根本不用时序预测社区的“通用 TSF SOTA”

如果“通用 TSF backbone”真的有像 NLP foundation model 那样的统治力，那么天气、金融、医疗、交通等领域的顶会/顶刊工作，理应大量复用这些 backbone。但论文里把现实摊开了：对应领域的研究在用的往往是领域定制的结构与 pipeline，而不是 TSF 社区那套 general-domain 架构（论文给了近三年多领域顶会/顶刊例子作为“生态证据”）。 TSF 社区在抛弃Domain先验去造“通用架构”，而各个领域在造“domain SOTA”。两条线越走越远。

4）“多域大数据”，其实远不够“规模化抹平一切”

很多 domain 的数据规模小得离谱，跟 NLP 那种“可并行收集的海量 token”完全不是一个物理世界。并且不仅小，还极端不均衡（有的域接近 200k timestamps，有的域聚合起来也就 2500）。

（二）这个 conflict 为什么“不可调和”

原因 A：跨域多样性是“信息形态差异”

不同领域的时序并不是“同一种序列换皮肤”，而是依赖完全不同的外生上下文与结构：

  • 天气预测靠空间场、地形、气压网格等；
  • 金融预测靠新闻情绪、订单簿、跨市场关联等；
  • 还有的域受明确物理定律约束，有的域是人类制度驱动的非平稳过程……

因此，不能通过增多domain，几十个domain的一些时序数据凑成一个数据集的形式来缓解数据的问题。

原因 B：时序数据有“时间物理约束”，规模化路径被堵死

时序数据不是互联网文本，不是想抓就能并行抓。

在固定观测窗口T下，即便提高采样频率或加传感器，信息增益仍受限；并且基础过程的逼近误差存在 O(1/sqrt(T)) 级别的时间边界。也就是说：我们无法靠“更密采样”无限逼近真相。

这会直接导向一个结果： 当我们没法用海量数据“洗掉”结构不匹配带来的损失时，想做高精度就必须注入领域先验；但领域先验又天然是 domain-dependent 的，于是 conflict 变成“结构性矛盾”。

（三）还能研究什么？要么限定Domain，要么用Meta-learning做泛化

要么，老老实实研究做Specific-Domain TSF。 要么，用比神经网络更有泛化性的方法做General-Domain TSF。

1：Domain-specific Neural Networks（DSNN）——窄，但深

我们明确倡导：与其在通用 benchmark 上追 0.1% 的平均提升，不如直接做 Domain SOTA：把领域结构、约束与生成机制写进模型/系统里。

2：Meta-learning——把“通用性”做成“会选模型的系统”

如果仍然想要跨域复用与统一接口，那就别强行统一 backbone，而是做“会挑专家”的 meta-system, LLM Scientist / agentic meta-learning, Learning-based meta-selection, Meta feature selection

Finally：别再做General Domain TSF了。

TSF 的 general-domain 之所以越来越像“榜单工程”、“特征工程”，不是因为大家不努力，而是因为在用一条 不适配时序本质约束 的路线硬卷：跨域多样性 + 时间物理约束 + 领域先验的不可统一，最终都会把 “one architecture” 推向失败。

我们希望能把讨论从“又一个在一张超大表格上拿到最多粗体的backbone”拉回到真正能用、真正有用、真正对Domain产生影响的方向：

  • 要么承认领域差异，去做 DSNN（真 SOTA，真可用）；
  • 要么把通用性上移，去做 meta-learning（真跨域，真系统）。
